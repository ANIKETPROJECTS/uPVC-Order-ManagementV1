---
name: Quotation-linked confirmations
description: Association rules for confirmation documents managed from the Confirmation / PO register.
---

The Confirmation register is confirmation-first: one row per reusable CF record with QT/MS links, linked order, PDF/Excel chips, record-level client decision, and shared revision history. Each revision needs one reason; files in a revision share its number, and a file-only revision warns when PDF and Excel latest versions differ. Do not overwrite order files when a CF advances: orders pin a version and must explicitly update or acknowledge keeping the old one. Do not show PO fields or order-only rows. PDF is proof only; only Excel is extracted. Keep legacy order documents accessible without guessing PDF/Excel pairings.

For confirmation workbooks uploaded to an order, automatically add valid, new schedule rows to the canonical window register after upload; skip matching window numbers and never overwrite existing rows. Overview and Windows must show the same complete register. Show the full extracted workbook details in Overview and Payments. Use the extracted Final Billing Amount to replace the saved order value when present, with Payments edit permission; never change the receipt ledger.

**Why:** The owner wants confirmation schedule rows linked to the order's shared window register, the common mesh type surfaced in Overview, and the confirmed final amount reflected in order balance calculations.

**How to apply:** Read and write the confirmation-record collection for the register. Validate QT/MS references, require a reason for every revision after v1, retain immutable version history, and store client decisions on the CF record. Newer version attachments still do not change production data automatically; direct order confirmation workbook uploads insert only valid, previously absent window numbers. Prefer the most common non-placeholder extracted mesh value and ignore outside aluminium and NA. Apply Final Billing Amount only through the existing Payments permission and billing validation; do not modify receipts. Show legacy order documents in order details rather than fabricating CF rows or copying one order decision onto multiple records.
