---
name: Installation and grievances
description: Product rules for delivered-order installation tracking and post-install customer grievance records.
---

**Rule:** Orders marked delivered by Dispatch appear in Installation automatically, and Installation editors may schedule any Client & Orders record, including inactive and not-yet-dispatched orders. Warn before scheduling inactive or not-yet-dispatched orders, but allow the user to continue. Saving a schedule must not change order or dispatch status; the schedule record is keyed to the order so selecting an already scheduled order edits that schedule rather than duplicating it. Manually scheduled orders appear in the register alongside delivered orders. Keep the assigned visit date separate from the actual installation date; completion and issue updates remain gated on delivery, and a new completion requires an assigned team and a visit date that has arrived in Asia/Kolkata. Team links should carry only the opaque order record ID and load order details behind Installation access. A successful installation advances the order lifecycle to installed; an issue requires a date and reason. Customer grievances can be added only after installation and belong in a dedicated tab on that order. Use Order Hub permissions for grievance access.

**Why:** Delivered orders must continue to enter Installation automatically, while editors need to plan visits for any order without changing its lifecycle. Confirmations make the risk of scheduling inactive or pre-dispatch work clear. Assignment links should not expose client or site details in their URL, and customer complaints should remain with their order.

**How to apply:** Keep the UI label mapping separate from the `delivered` API/database enum. Include delivered orders plus any scheduled order in the Installation register; list all orders in the scheduler for Installation editors and clearly label inactive orders and each order's current status. Require confirmation for inactive and pending-dispatch orders. Preserve lifecycle changes, required issue details, grievance gating, order association, and permission scope. Compare visit dates using the Asia/Kolkata calendar day and display link details only from the protected order API.
