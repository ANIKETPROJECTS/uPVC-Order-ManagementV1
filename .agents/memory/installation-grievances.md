---
name: Installation and grievances
description: Product rules for delivered-order installation tracking and post-install customer grievance records.
---

**Rule:** Orders marked delivered by Dispatch appear in Installation automatically, and Installation editors may also schedule any active order before dispatch. Saving a schedule must not change dispatch status; manually scheduled orders appear in the register alongside delivered orders. Keep the assigned visit date separate from the actual installation date; completion and issue updates remain gated on delivery, and a new completion requires an assigned team and a visit date that has arrived in Asia/Kolkata. Team links should carry only the opaque order record ID and load order details behind Installation access. A successful installation advances the order lifecycle to installed; an issue requires a date and reason. Customer grievances can be added only after installation and belong in a dedicated tab on that order. Use Order Hub permissions for grievance access.

**Why:** Delivered orders must continue to enter Installation automatically, while editors also need to plan visits for active orders before Dispatch. Keeping dispatch state unchanged separates planning from delivery and actual completion. Assignment links should not expose client or site details in their URL, and customer complaints should remain with their order.

**How to apply:** Keep the UI label mapping separate from the `delivered` API/database enum. Include delivered orders plus any scheduled order in the Installation register; keep the schedule picker limited to active orders and Installation edit access. Do not allow completion or issue updates before delivery. Preserve lifecycle changes, required issue details, grievance gating, order association, and permission scope. Compare visit dates using the Asia/Kolkata calendar day and display link details only from the protected order API.
